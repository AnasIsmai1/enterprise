    **Step 1: Create WebhookService (src/modules/subscription/application/services/webhook.service.ts)**

    Following Research Pattern 6 (Stripe Webhook Idempotency). Inject: `Repository<WebhookEvent>`, `Repository<Subscription>`, `Repository<Users>`, `AuditLogService`.

    Main method:
    ```typescript
    async processEvent(event: Stripe.Event): Promise<void>
    ```
    - Check idempotency: find `webhookEventRepo.findOne({ where: { stripeEventId: event.id } })`
    - If exists and status === 'processed', return immediately
    - Insert/upsert with `status: 'processing'` (UNIQUE constraint prevents concurrent duplicates)
    - Try/catch the handler switch:
      - `checkout.session.completed` -> handleCheckoutCompleted (SUB-10)
      - `customer.subscription.created` -> handleSubscriptionCreated (SUB-05)
      - `customer.subscription.updated` -> handleSubscriptionUpdated (SUB-06)
      - `customer.subscription.deleted` -> handleSubscriptionDeleted (SUB-07)
      - `invoice.payment_succeeded` -> handlePaymentSucceeded (SUB-09)
      - `invoice.payment_failed` -> handlePaymentFailed (SUB-08)
    - On success: update webhook event to `status: 'processed', processedAt: new Date()`
    - On failure: update to `status: 'failed', error: err.message`, re-throw (so Stripe retries)

    Handler implementations:

    - `handleCheckoutCompleted(session: Stripe.Checkout.Session)`:
      - Extract userId from `session.metadata.userId`
      - Extract stripeSubscriptionId from `session.subscription`
      - Retrieve subscription details from Stripe: `stripe.subscriptions.retrieve(stripeSubscriptionId)`
      - Create/update Subscription entity: set stripeCustomerId, stripeSubscriptionId, status, plan (derive from price ID), period dates, trial end
      - Update `user.role = UserRole.PREMIUM` (LOCKED DECISION: optimistic premium access)
      - Log audit event

    - `handleSubscriptionCreated(sub: Stripe.Subscription)`:
      - Find subscription by stripeSubscriptionId
      - Update status, period dates, trial end

    - `handleSubscriptionUpdated(sub: Stripe.Subscription)`:
      - Update subscription status, plan, period dates
      - If plan changed (monthly <-> annual), update plan field
      - If status changed to 'canceled' or 'unpaid', update accordingly

    - `handleSubscriptionDeleted(sub: Stripe.Subscription)`:
      - LOCKED DECISION: This is when we actually downgrade. Stripe dunning handles retries; we only act here.
      - Set subscription status to 'canceled'
      - Set `user.role = UserRole.FREE`
      - Log audit event (downgrade)

    - `handlePaymentSucceeded(invoice: Stripe.Invoice)`:
      - If subscription exists, update status to 'active' (from 'past_due' or 'trialing')
      - Update currentPeriodStart/End from invoice

    - `handlePaymentFailed(invoice: Stripe.Invoice)`:
      - Set subscription status to 'past_due'
      - LOCKED DECISION: Do NOT downgrade here. Let Stripe dunning handle retries. Downgrade only on `subscription.deleted`.

    - `POST /v1/subscriptions/webhook` — `@AllowAnonymous()` (Stripe doesn't send auth). Raw body signature verification (SUB-13, Research Pattern 5):
      ```typescript
      @Post('webhook')
      @AllowAnonymous()
      async handleWebhook(
        @Req() req: Request,
        @Headers('stripe-signature') signature: string,
      ) {
        const rawBody = (req as any).rawBody as Buffer;
        const event = this.stripeService.constructEvent(rawBody, signature);
        await this.webhookService.processEvent(event);
        return { received: true };
      }
      ```
      NOTE: `rawBody` is available because Plan 01 set `enableRawBodyParser: true` in AuthModule.forRoot.

    All authenticated endpoints use `@CurrentUser()` or `@Session()` decorator.
    All endpoints use `@ApiTags('Subscriptions')` and proper Swagger decorators.
