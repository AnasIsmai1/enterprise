3. `getSignedUrl(bucket: Bucket, key: string): Promise<string>` — Returns a signed URL with 1-hour expiry (FILE-03). Redis-cached with 50-minute TTL (locked decision: cache TTL slightly less than URL expiry):
```typescript
async getSignedUrl(bucket: Bucket, key: string): Promise<string> {
  const cacheKey = `signed_url:${bucket}:${key}`;
  const cached = await this.redis.get(cacheKey);
  if (cached) return cached;

  const client = this.getClient(bucket);
  const command = new GetObjectCommand({ Bucket: bucket, Key: key });
  const url = await getSignedUrl(client, command, { expiresIn: 3600 }); // 1 hour

  await this.redis.setex(cacheKey, 3000, url); // Cache for 50 min
  return url;
}
```

Import `getSignedUrl` from `@aws-sdk/s3-request-presigner`.

  await this.redis.del(`signed_url:${bucket}:${key}`);

**Phase B: Rewrite EmailService to enqueue via BullMQ (locked decision: async, non-blocking)**

Completely rewrite `src/external/email/email.service.ts`. Delete everything in the current file and rebuild from scratch. The current implementation uses synchronous axios calls with raw HTML templates — this is entirely wrong.

New implementation:

```typescript
import { Injectable } from '@nestjs/common';
import { InjectQueue } from '@nestjs/bullmq';
import { Queue } from 'bullmq';
import { EmailType, EMAIL_QUEUE, EmailJobData } from './email.types';

@Injectable()
export class EmailService {
  constructor(
    @InjectQueue(EMAIL_QUEUE) private readonly emailQueue: Queue,
  ) {}

  /**
   * Enqueue an email for async sending via BullMQ.
   * The processor handles Brevo API calls with automatic retries.
   *
   * Usage: emailService.send(EmailType.VERIFICATION, { to: 'user@example.com', params: { verificationUrl: '...' } })
   */
  async send(type: EmailType, payload: { to: string; params: Record<string, any> }): Promise<void> {
    const jobData: EmailJobData = {
      type,
      to: payload.to,
      params: payload.params,
    };

    await this.emailQueue.add(type, jobData, {
      attempts: 3,                              // Retry 3 times on failure
      backoff: { type: 'exponential', delay: 2000 }, // 2s, 4s, 8s
      removeOnComplete: true,                   // Clean up successful jobs
      removeOnFail: false,                      // Keep failed jobs for debugging
    });
  }
}
```

Key points:
- The `send()` method ONLY enqueues — it does NOT call Brevo API. This is the locked decision from CONTEXT.md.
- The method is non-blocking to API responses.
- BullMQ handles retries automatically on Brevo API failures.

**Phase C: Create EmailProcessor — BullMQ worker that calls Brevo API**

Create `src/external/email/email.processor.ts`:

```typescript
import { Processor, WorkerHost } from '@nestjs/bullmq';
import { Job } from 'bullmq';
import { Logger } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import * as Brevo from 'brevo';
import { EmailJobData, EMAIL_QUEUE, EMAIL_TEMPLATE_IDS } from './email.types';

@Processor(EMAIL_QUEUE)
export class EmailProcessor extends WorkerHost {
  private readonly logger = new Logger(EmailProcessor.name);
  private readonly apiInstance: Brevo.TransactionalEmailsApi;

  constructor(private readonly config: ConfigService) {
    super();
    this.apiInstance = new Brevo.TransactionalEmailsApi();
    this.apiInstance.setApiKey(
      Brevo.TransactionalEmailsApiApiKeys.apiKey,
      this.config.get('email.brevoApiKey'),
    );
  }

  async process(job: Job<EmailJobData>): Promise<void> {
    const { type, to, params } = job.data;
    const templateId = EMAIL_TEMPLATE_IDS[type];

    this.logger.log(`Processing email job: ${type} to ${to} (template: ${templateId})`);

    const sendSmtpEmail = new Brevo.SendSmtpEmail();
    sendSmtpEmail.to = [{ email: to }];
    sendSmtpEmail.templateId = templateId;
    sendSmtpEmail.params = params;
    sendSmtpEmail.sender = {
      email: this.config.get('email.senderEmail'),
      name: this.config.get('email.senderName'),
    };

    try {
      await this.apiInstance.sendTransacEmail(sendSmtpEmail);
      this.logger.log(`Email sent successfully: ${type} to ${to}`);
    } catch (error) {
      this.logger.error(`Failed to send email: ${type} to ${to}`, error);
      throw error; // Re-throw so BullMQ retries
    }
  }
}
```

Note on the Brevo SDK: The `brevo` package v1.0.0 is already installed. The exact API may differ slightly from the above — the executor should verify the import path and API key setup method by checking the `brevo` package's type definitions or documentation. The core pattern is: create TransactionalEmailsApi instance, set API key, call sendTransacEmail with templateId + params. If the SDK API has changed, adapt accordingly but keep the same pattern.
